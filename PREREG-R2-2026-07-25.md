## 7. Abort / integrity conditions (binding on the coordinator)

1. **Extraction-integrity invariant (RUNBOOK.md:324-362):** after every extraction, the terminal record (`extraction.integrity-<YYYYMMDD>.log`, correlated by `job_id` and/or `session_fp`, scoped by `org_id`) MUST exist and correlate. If the matching terminal record is **missing** or **uncorrelatable**, or it reports `resolved_problem_count == 0 && emitted_memory_count > 0` (`invariant_violation == true`), the coordinator MUST **ABORT the whole benchmark BEFORE** `m2_proof.leader_verify_and_commit`; MUST NOT continue, self-heal, retry around the violation, or approve/commit the memory; preserve logs + checkpoint; escalate. Never infer an invariant pass from the absence of a violation flag; a `completed` record lacking episode-count fields or `invariant_violation` is uncorrelatable-for-invariant → abort-worthy under the missing-record rule. Smart-leader `deny_final` does NOT supersede this abort.
2. **Zero-progress ⇒ zero memories is in-product and is the EXPECTED SHAPE, not a violation** (canonical mcp `c5304d9` fail-closed gate, live on the clone): a session with `resolved == 0` makes no extraction LLM call, emits zero memories, and leaves a byte-compatible terminal integrity record with `empty_reason: zero_progress` / `invariant_violation: false`. If the OFF baseline resolves zero problems, the ON arm runs with an empty corpus and says so — that IS a reportable R2 shape (see §9 fork).
3. **Run-timeout 5400s per attempt** (`wevibe_bench/adapters/backgammon.py:153` `DEFAULT_RUN_TIMEOUT_S = 5400`; `scripts/backgammon_scored_ladder.py:74`). A wall-clock kill feeds trigger T3.
4. **Poller liveness:** any long run is watched by a poller enforcing the **3-signal liveness / 900s window** standing constraint (diary §21 sourced lesson; workspace rule R-31): no new progress in 900s = treat as hung → kill + orphan check + report how far it got. The poller never launches/edits/judges the run.
5. **Prompt via STDIN, never argv** (BENCHMARK-STATE.md:306-312, defect D6): argv-carried prompts previously self-matched worker cleanup `pkill` patterns and killed the opencode process; the harness delivers the prompt by piped STDIN (`docker exec -i`) and logs `op=worker-stdin-write … text_fp=…`.
6. **Pricing gate at run start:** with `--authorize` + upstream `orcarouter`, the proxy fetches live orcarouter pricing and verifies the gate BEFORE any paid call; on `PricingGateError` it logs `event="pricing_gate" status="failed"` and refuses all paid calls (exit 2) (`openrouter_proxy_server.py:1200-1229`; `verify_orcarouter_pricing_gate` `openrouter_proxy.py:564`). Pricing snapshots are never baked into code (RUNBOOK.md:163-165).
7. **Settlement + reconcile:** per-request proven-settle `derived_settlement` events in the proxy cost ledger (`openrouter_proxy_server.py:517-534`; unproven requests retained via `retain_unproven`), and the smart-leader `reconcile-inventory` step at the `AWAIT_COORDINATOR_REVIEW` boundary reconciles authoritative chain/hub committed inventory against the private benchmark catalog, fail-closed on `--require-complete` (RUNBOOK.md:393-402).
8. **402-truncation is never scored FAIL** (diary §21 standing constraint); termination honesty per D-BENCH-INTEGRITY §1.
9. **Problem→memory quantity mapping (diary §22.3):** one resolved problem ≈ one atomic memory candidate. A run solving N problems but producing ≈0 or ≫N candidates is a measurement red flag to INVESTIGATE (extraction under/over-production) — NOT an automatic abort.

## 9. Success / failure framing (diary §18 pragmatic bar)

Diary §18 (verbatim):

> Success/failure framing follows Walter’s pragmatic bar: the benchmark exists to show WeVibe improves the LLMs using
> it. Improvement must be visible in the ON-run progress vector (more problems resolved; fewer cycles, tool calls,
> tests, tokens, wall time; attempts-to-green trending down). Failure means no demonstrable improvement or an integrity
> collapse severe enough to invalidate the run.

Applied to R2:

- **Self-lift evidence:** the ON run shows improvement over the OFF baseline on the progress vector (primaries: problems-resolved, attempts-to-green; tokens secondary).
- **No improvement = a production defect in extraction/prompting to fix FIRST** — that IS the R2 fork. If GLM's own memories demonstrably delivered (D-E = `YES`) yet produce no lift, the defect lives in the extraction→commit→recall→inject production path, and fixing it precedes any redesign conclusion.
- **Failure is information.** An honest "no lift" at N=1 triggers the variance policy (escalation to N=3 if a trigger fires) and a defect investigation — never a silent re-run, never a relabel.
- **No redesign conclusions from N=1.** Per VARIANCE-POLICY, N=1 is honest about single-run variance, "instead of pretending N=1 is statistics."
